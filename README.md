# reqcheck — агент проверки требований

ИИ-агент статической проверки документа с требованиями: выделяет требования, проверяет каждое и набор
целиком по ISO/IEC/IEEE 29148:2018 (п. 5.2.5, 5.2.6) и IEEE 830-1998 (п. 4.3) и пишет отчёт на русском.

Хакатон BCC-HUB × MNU FinTech.

> **Состояние: в разработке.** Все этапы работают, отчёт выпускается. Прогон с живой моделью ещё
> не выполнялся, метрики точности не измерены.

## Установка

Нужен [uv](https://docs.astral.sh/uv/); Python 3.11+ он поставит сам.

```bash
uv sync
```

## Ключ модели

1. Получить ключ Gemini API: <https://aistudio.google.com/> → **Get API key**. Бесплатного тарифа достаточно.
2. Скопировать пример конфига и вписать ключ:

```bash
cp .env.example .env
```

Файл `.env` в репозиторий не попадает.

## Запуск

Одна команда: путь к документу и путь к отчёту.

```bash
uv run reqcheck docs/requirements.pdf reports/report.md
```

Отчёт ляжет в файл из второго аргумента; папка создаётся сама.

Без ключа (или с флагом `--no-llm`) агент работает только правилами: проверка набора требований
моделью не выполняется, и это отмечено в паспорте и итоге отчёта. Если модель отказала посреди
прогона (квота, сеть), отчёт всё равно выпускается — с причиной сбоя в паспорте.

Коды выхода:

| Код | Значение |
|---|---|
| 0 | отчёт создан, итог GO или CONDITIONAL GO |
| 1 | отчёт создан, итог NO-GO |
| 2 | отчёт не создан: плохой вход, сбой модели, этап не готов |

## Как устроено

```
cli.py            разбор аргументов, сообщения об ошибках без traceback
pipeline.py       порядок этапов
models.py         контракты данных между этапами
llm.py            контракт вызова модели и схемы её ответов
errors.py         коды выхода и ошибки для пользователя
stages/
  reader.py       чтение документа и preflight
  registry.py     реестр требований
  rules.py        правила без модели
  checks.py       проверки с моделью: каждое требование и набор
  grounding.py    проверка цитат, разметка по справочнику
  report.py       паспорт, сводка, итог
  render.py       отчёт в Markdown
```

Принцип: модель называет тип дефекта из закрытого списка и приводит дословные цитаты. Номера строк,
серьёзность, пункт стандарта и итог ставит код. Замечание, цитата которого не найдена в документе,
в отчёт не попадает.

## Разработка

```bash
uv run pytest
uv run ruff check .
```

Тест против подгонки под конкретный документ: падает, если в коде, промптах или тестах есть
идентификатор, число или фраза из проверяемого ТЗ. Словарь не хранится в репозитории — он строится
из самого документа при запуске:

```bash
REQCHECK_ISSUED_DOC=/путь/к/выданному/ТЗ.md uv run pytest tests/test_no_overfit.py
```

Этап реализуется в своём модуле `stages/` и меняет только его. Сигнатуры функций и модели из
`models.py` и `llm.py` — общий контракт: менять их только вместе с тестами и с предупреждением
остальным.
